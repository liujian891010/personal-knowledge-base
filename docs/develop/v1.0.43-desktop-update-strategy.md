# v1.0.43 Desktop Update Strategy

## Decision

V1 does not enable automatic desktop updates.

The desktop installer is distributed as a manually downloaded, signed Windows package. Users upgrade by downloading the next signed installer and running it over the existing installation. The app data directory, workspace registry, login session, diagnostics, and local workspace content are not stored in the install directory, so an in-place reinstall must not remove user data.

## Why Auto Update Is Off For V1

Automatic update is deferred because V1 does not yet have all of the release controls required for a safe updater channel:

1. A stable signed update feed URL.
2. A rollback policy for bad releases.
3. Delta/full package retention rules.
4. A user-facing update prompt and release note surface.
5. CI verification that the update package, installer signature, and installed app signature all match the same release version.

Enabling an updater before those controls exist would add a silent remote code delivery path without enough operational guardrails.

## Manual Upgrade Path

1. Build the Windows package with `npm.cmd run dist:win:signed`.
2. Verify `release/*.exe` with `npm.cmd run verify:win-signature`.
3. Publish the installer and checksum through the approved release channel.
4. Tell users to close NoteAI before installing.
5. Users run the new installer and keep the default install location unless they intentionally installed elsewhere.
6. After launch, users can export a desktop diagnostics package if the bridge fails to start.

## Rollback Path

If a release is bad, publish the previous signed installer as the rollback package and mark the bad installer as withdrawn in the release notes. Users run the previous installer over the current installation. Workspace data remains in the user-selected vault and Electron `userData`, not in the app install directory.

## Future Auto Update Gate

Auto update can be enabled after all of the following are true:

1. A signed update feed is hosted on HTTPS.
2. Release CI runs package build, install smoke, signature verification, and update feed validation.
3. The app exposes an update prompt with version, size, release notes, and restart timing.
4. Rollback and yanked-release handling are documented.
5. The update channel is configurable for stable/test rings.

Until then, V1 release notes must explicitly state that upgrades are manual.
