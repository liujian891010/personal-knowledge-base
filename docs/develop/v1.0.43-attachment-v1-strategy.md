# v1.0.43 附件 V1 开放策略

## 结论

V1 采用“受控开放”策略：附件进入正式工作流，但只作为二进制资源管理，不提供在线编辑能力。

## V1 范围

- 允许用户通过前端导入附件，统一写入 workspace 相对目录 `Attachments/`。
- 附件进入 `filemap.json`，类型为 `attachment`，参与同步 manifest 与 blob 提交。
- Markdown 笔记中插入附件相对路径，优先使用 `![name](../Attachments/name.ext)` 或 `[name](../Attachments/name.ext)`。
- 文件树展示附件，但与 Markdown 笔记区分图标、类型和可操作按钮。
- PDF、图片和未知二进制文件只支持基础预览或外部打开；不做内嵌编辑。
- 删除、恢复附件必须走 filemap/tombstone 语义，不能只删除磁盘文件。

## V1 不做

- 不支持附件在线编辑、批注或 PDF 深度解析。
- 不支持任意目录散落附件；前端导入统一落 `Attachments/`。
- 不支持把 `.noteapp/`、`.ai/raw/` 等保留目录作为附件来源或目标。
- 不在 AI Wiki 编译中自动解析附件内容；后续单独排期。
- 不承诺大附件断点续传；大附件进度和续传归入 M2 断点续传任务。

## 后续任务边界

- `V1043-M1-08`：实现前端导入入口和文件树展示；导入成功后返回 Markdown 相对路径。
- `V1043-M1-09`：实现 PDF/图片基础预览或外部打开按钮；未知类型必须有明确降级提示。
- `V1043-M1-10`：补附件删除、恢复、同步边界测试；确保不会破坏 filemap、tombstone 和跨端打开。

## 验收口径

- 附件导入后位于 `Attachments/`，同名文件自动生成不冲突路径。
- 附件 `file_id` 稳定，进入同步 manifest，而不是游离于 filemap 之外。
- Markdown 中的相对链接在跨端同步后仍可打开。
- 删除/恢复附件后，回收站和 tombstone 记录可解释。
