# v1.0.43 Object Storage Operations Plan

Date: 2026-05-19

This plan closes the current PROD-03 boundary for encrypted blob storage. The
backend continues to proxy encrypted bytes through server-controlled upload and
download capabilities; production deployments must configure S3/OSS operations
policy explicitly.

## Required Production Configuration

When `NOTEAPP_SERVER_ENV=production` and `NOTEAPP_SERVER_BLOB_STORAGE=s3` or
`oss`, the server requires:

| Variable | Purpose |
| --- | --- |
| `NOTEAPP_SERVER_OBJECT_ENDPOINT` | HTTPS S3/OSS-compatible endpoint |
| `NOTEAPP_SERVER_OBJECT_BUCKET` | Single bucket used for encrypted vault blobs |
| `NOTEAPP_SERVER_OBJECT_REGION` | Signing region |
| `NOTEAPP_SERVER_OBJECT_ACCESS_KEY_ID` | Access key id from the deployment secret store |
| `NOTEAPP_SERVER_OBJECT_SECRET_ACCESS_KEY` | Secret access key from the deployment secret store |
| `NOTEAPP_SERVER_OBJECT_CREDENTIAL_ROTATION_DAYS` | Maximum credential age before rotation |
| `NOTEAPP_SERVER_OBJECT_LIFECYCLE_RETENTION_DAYS` | Minimum lifecycle/retention window for blob recovery |
| `NOTEAPP_SERVER_OBJECT_ALERT_DESTINATION` | Alert route for object-storage failures |
| `NOTEAPP_SERVER_OBJECT_LEAST_PRIVILEGE_POLICY` | Must be `single-bucket-read-write` |

The secret values are not returned from diagnostics. The non-secret operations
policy is returned from `GET /health/dependencies` under the blob-store
diagnostics payload.

## Least-Privilege Policy

Production object credentials should be scoped to one bucket and only the object
prefix used by the server, currently:

```text
vaults/<vault_id>/blobs/<sha256(blob_id)>
```

The application needs object put, object get, and ranged object get for that
prefix. Bucket administration, bucket deletion, ACL mutation, public object
policy changes, and cross-bucket access are outside the application role.

## Credential Rotation

1. Store object credentials in the deployment secret manager, not in source code
   or checked-in fixtures.
2. Rotate at or before `NOTEAPP_SERVER_OBJECT_CREDENTIAL_ROTATION_DAYS`.
3. Deploy the new secret pair.
4. Run `GET /health/dependencies` and one blob upload/download smoke.
5. Revoke the old key after the new deployment is healthy.

## Bucket Lifecycle And Recovery

Enable bucket versioning or provider-equivalent recovery features when
available. Lifecycle expiration must not be shorter than
`NOTEAPP_SERVER_OBJECT_LIFECYCLE_RETENTION_DAYS`; object deletion automation must
be coordinated with sync tombstone retention and backup drills.

## Alerting

`GET /metrics` exposes `object_storage_failures_total` and blob upload failure
counters. Production monitoring should alert when object-storage failures are
non-zero in a short window or when the failure rate increases after deployment.
`NOTEAPP_SERVER_OBJECT_ALERT_DESTINATION` records the owning alert route in
configuration and diagnostics.

## Verification

Automated coverage:

1. Production S3/OSS rejects missing operations policy.
2. Production S3/OSS rejects non-HTTPS endpoints.
3. Health diagnostics include non-secret operations policy values.
4. Production smoke verifies an S3/OSS-compatible outage returns
   `object_storage_unavailable`.
5. Metrics increment `object_storage_failures_total` on object-storage failure.
