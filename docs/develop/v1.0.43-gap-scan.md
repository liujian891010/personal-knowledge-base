## 必须完成

以下项目直接对应方案 V1 必须闭环，或属于当前 MVP 继续走向可发布版本的阻塞项。

### 1. 自动保存与草稿恢复

当前编辑器仍以手动保存为主。

方案要求：

1. 用户停止输入后约 1 秒自动保存到本地文件系统
2. 编辑开始后写入 `.noteapp/drafts/<file_id>.draft`
3. 草稿写入使用 tmp + rename 原子替换
4. 保存成功后清理草稿
5. 启动时发现草稿后提示恢复未保存内容

这是当前 Markdown 编辑器最直接的产品缺口，建议优先实现。

### 2. 本地搜索

当前 SQLite 中已有 `search_index / FTS` 相关结构迹象，但还缺完整闭环：

1. 索引维护
2. 搜索 CLI / 桥接 API
3. 前端搜索入口
4. 搜索结果跳转文件
5. 搜索结果更新和增量重建策略

本地搜索是 Obsidian 类知识库基础能力，应排在 AI 前面完成。

### 3. 双向链接与反向链接

当前还没有完整的 `[[wiki link]]` 解析和反链体验。

需要补齐：

1. Markdown 正文中的 `[[...]]` 解析
2. `note_links` 索引表或等价结构
3. 文件重命名时链接处理策略
4. 当前笔记的反向链接面板
5. 从链接点击跳转对应文档

该项是方案 V1 桌面端明确要求。

### 4. 新建、重命名、移动、删除文档的 UI 闭环

当前前端主要覆盖浏览和编辑已有文件。

仍需实现：

1. 新建 Markdown 笔记
2. 应用内重命名 / 移动
3. 删除文档
4. 删除后状态进入 filemap / tombstone
5. 删除和同步状态联动
6. 应用内重命名保持同一 `file_id`，不得退化为删除 + 新建

这些操作是完整笔记软件的基础工作流。

### 5. 附件插入与预览

方案 V1 要求附件插入与预览。

当前缺：

1. 附件导入到 Vault
2. 附件 filemap 登记
3. Markdown 中插入相对路径
4. 图片 / PDF 等基础预览
5. 附件同步和迁移边界验证

### 6. 真实 E2EE

当前 desktop crypto 仍存在 placeholder 实现。

必须替换为真实加密 Provider：

1. vault key / content key 派生
2. blob 加密和解密
3. nonce 派生
4. 本地安全存储
5. 错误密码和恢复流程
6. 与 blob 去重、manifest、上传下载能力联调

这是方案 V1 同步能力中的硬要求。

### 7. AI 知识库能力

`packages/ai-core` 当前仍是占位。

方案 V1 要求至少具备：

1. AI 对话窗口
2. 当前笔记总结
3. 文件夹总结
4. 搜索结果总结
5. 引用式回答
6. 生成 `.ai/wiki/` 知识页
7. 维护 `.ai/index.md`
8. 结果插入当前笔记或新建知识页
9. 基于知识页的桌面端问答 MVP

AI 是方案的核心差异化能力，但建议排在自动保存、搜索、双链之后。

### 8. 生产化后端

当前后端 README 明确存在生产缺口：

1. 无账号模型
2. 无持久数据库
3. 无真实对象存储
4. token 过期和刷新机制不足
5. 无 tombstone garbage collection policy
6. 单进程 JSON store，缺少跨进程 CAS 锁

若目标是可发布产品，必须替换当前本地开发服务。

### 9. 设备管理与 tombstone 回收闭环

当前已有设备注册 / 撤销和 ack 基础，但缺完整产品闭环：

1. 设备列表 UI
2. heartbeat / last_seen_at
3. 每设备 `acked_revision` 展示
4. 移除设备确认
5. 移除后 token / capability 撤销
6. 移除后重新判定 tombstone 回收资格

这是方案同步 V1 的明确要求。

## 可延后

以下内容方案中已明确不是当前 V1 主线，或当前 MVP 文档已收口延后。

1. 移动端完整实现：方案定位为 V1.1，不阻塞桌面 V1。
2. 图谱真实关系可视化：应等双向链接索引完成后再做。
3. 回收站完整 UI：可等删除语义和 tombstone 闭环稳定后实现。
4. 仪表盘真实数据化：不影响核心写作、同步和 AI 闭环。
5. 插件市场：方案明确 V1 不做。
6. 多人实时协作：方案明确 V1 不做。
7. Git / WebDAV 多协议同步：方案明确 V1 不做。
8. 富文本所见即所得编辑器：方案明确 V1 不做，继续坚持 Markdown 原文优先。
9. 复杂版本回滚 UI：方案明确 V1 不做。
10. 大型 Agent 工作流平台：方案明确 V1 不做。

## 建议实现顺序

建议后续按以下顺序推进：

1. 自动保存与草稿恢复
2. 本地搜索
3. 双向链接与反向链接
4. 新建 / 重命名 / 移动 / 删除文档
5. 附件插入与预览
6. 真实 E2EE
7. 设备管理与 tombstone 回收 UI
8. AI 知识库 MVP
9. 生产化后端

理由：

1. 自动保存最贴近当前 Markdown 编辑器，范围最小，收益直接。
2. 搜索和双链是 Obsidian 类工具的基础能力，且是 AI 知识编译前的索引基础。
3. 文件 CRUD 必须稳定后，附件、同步、AI 写回才有可靠边界。
4. E2EE 和生产后端投入较大，应在本地核心体验稳定后推进。
5. AI 是产品差异化核心，但不能建立在缺搜索、缺双链、缺文件操作的基础上。

## 下一步建议

下一步优先实现“自动保存与草稿恢复”：

1. 前端编辑器输入 debounce 触发保存
2. 桥接 / desktop CLI 增加 draft 写入和清理能力
3. 启动或加载文件时检测 draft
4. 前端提示恢复或丢弃草稿
5. 增加 e2e smoke 覆盖异常草稿恢复路径
