本扫描用于判断当前仓库距离方案 V1 还缺哪些部分，并区分“已经收口”“仍需完成”“可延后”。本文件反映当前实现状态，不再沿用最初 gap-scan 中已经过期的结论。

## 当前已收口

### 1. Markdown 编辑基础闭环

已具备：

1. 选择本机工作区文件夹。
2. 初始化并导入工作区文件。
3. 展示本地文件树。
4. Markdown 编辑、预览、分栏。
5. 写回本地文件系统。
6. 保存后刷新 workspace / sync 快照。
7. 工作区浏览当前只展示 Markdown 文件；非 Markdown 文件不会进入 Markdown 编辑器。
8. `.ai/` 作为系统目录从普通笔记库浏览中隐藏。

### 2. 自动保存与草稿恢复

已具备：

1. 编辑器输入后写入 `.noteapp/drafts/<file_id>.draft`。
2. 草稿写入使用服务端原子写入路径。
3. 正式保存成功后清理草稿。
4. 加载文件时检测草稿。
5. 前端提供恢复 / 丢弃草稿入口。
6. 自动保存会写回本地文件。

后续可优化：

1. 草稿冲突提示文案。
2. 大文件和二进制附件的草稿保护提示。
3. 更精细的保存状态展示。

### 3. 本地搜索 MVP

已具备：

1. SQLite search index / FTS 路径。
2. `rebuild-search-index` CLI。
3. `search-workspace` CLI。
4. bridge `/api/workspace/search`。
5. 前端搜索输入和结果跳转。
6. 搜索跳转后选中状态正确刷新。

后续可优化：

1. 搜索索引已从查询时全量 rebuild 改为变更点维护，手动 rebuild 保留为修复入口。
2. 搜索结果 snippet / 高亮仍比较基础。
3. 暂无范围过滤、类型过滤、最近文件排序。
4. 暂无搜索结果总结。

### 4. 双链 / 反链 MVP

已具备：

1. Markdown 正文 `[[...]]` 解析。
2. note links 索引写入。
3. outgoing links 与 backlinks 查询。
4. bridge links API。
5. 前端详情面板展示出链和反链。
6. 点击可跳转到目标文件。

后续可优化：

1. 重命名文件时会改写指向旧标题的 wiki link，并保留锚点和别名。
2. 未解析链接已提供创建入口，可从详情面板直接创建目标笔记。
3. 别名、标题匹配、大小写策略仍需产品化。
4. 图谱视图还不是基于真实关系的完整体验。

### 5. Markdown 文档 CRUD 与回收站

已具备：

1. 新建 Markdown 文档。
2. 重命名仅修改原文件名，不移动目录。
3. 删除进入 `.noteapp/trash`，不直接永久删除。
4. filemap 保留同一 `file_id`。
5. 回收站列表、恢复、单个彻底删除、清空。
6. 删除弹窗和重命名弹窗使用应用内 UI，不依赖浏览器原生 confirm / prompt。
7. 缺失 trash 文件可 purge，避免卡死。

后续可优化：

1. 还未实现应用内移动文件。
2. 附件 CRUD 还未完整开放。
3. 删除 / 恢复后的同步状态说明还可以更清晰。

### 6. AI Wiki 编译 MVP

已具备：

1. `packages/ai-core` 确定性编译器。
2. `compile-ai-wiki` CLI。
3. bridge `/api/ai/wiki/compile`。
4. 前端 AI Wiki 页面。
5. 生成 `.ai/index.md`。
6. 生成 `.ai/wiki/*.md`。
7. 记录 `.ai/log.md`。
8. 支持 `locked: true` / `user_edited: true` 页面跳过覆盖。
9. 支持未变化页面跳过写入。
10. AI Wiki 页面展示结构化 frontmatter。

当前限制：

1. 这是确定性编译 MVP，不是真正 LLM 总结。
2. AI Wiki Ask 已可在存在 citations 时调用已配置 provider；无 citations 时不会调用模型，并提示先编译/刷新检索。
3. 暂无搜索结果总结。
4. 暂无结果插入当前笔记。
5. AI Wiki 页面实现仍在，但当前导航默认隐藏，不计入已开放用户入口。

### 7. 同步核心 MVP

已具备：

1. filemap 管理。
2. tombstone ledger。
3. SQLite vault state / journal。
4. pull / apply / commit 流程。
5. local change detection。

### 8. 多工作区基础闭环（首版）

已具备：

1. workspace registry 持久化。
2. `GET /api/workspaces`、`POST /api/workspaces`、`POST /api/workspaces/select-folder`、`DELETE /api/workspaces/:id`、`POST /api/workspaces/:id/activate`。
3. 顶部工作区切换器、切换确认弹窗、切换中的 loading 遮罩。
4. 无活动工作区时的工作区引导页。
5. 工作区切换后刷新文件树、本地设置快照和 AI 文档上下文。

### 9. AI 文档上下文与会话持久化

已具备：

1. 从文件夹或多选 Markdown 文档进入 AI 上下文。
2. 在 AI 文档页持续多轮提问。
3. 已选文档支持继续添加、局部移除和 Markdown 预览弹窗。
4. AI 文档会话本地持久化到 `.noteapp/ai-chats`。
5. 会话列表、切换、删除和自动保存。

当前限制：

1. 当前只有 `preview` 输出，没有“插入当前笔记”或“保存为新知识页”。
2. 暂无“当前笔记总结”“搜索结果总结”入口。
3. 暂无流式回答。

### 10. 登录最小闭环

已具备：

1. 初次进入应用要求输入 `appKey`。
2. 调用公司登录接口校验 `resultCode = 1` 后才算登录成功。
3. 登录信息写入 `sessionStorage.userInfo`。
4. 顶部展示 `userName` 并支持退出登录。

当前限制：

1. 这是前端壳层登录，不等于同步服务端的正式账号体系。
2. 登录态只保存在 `sessionStorage`，刷新浏览器进程或新开会话后需重新登录。

## 2026-05-11 update: AI model provider

Implemented:
- Desktop AI Ask supports an OpenAI-compatible chat completions provider.
- Configure with `NOTEAPP_AI_API_KEY` and `NOTEAPP_AI_MODEL`; `NOTEAPP_AI_BASE_URL` defaults to `https://api.openai.com/v1`.
- `NOTEAPP_AI_TIMEOUT_SECONDS` is optional and defaults to `30`.
- The provider uses existing `.ai/wiki` citations as bounded context and returns a natural-language answer.
- Missing config or provider failure keeps the deterministic local fallback.
- Frontend Ask copy now reflects provider vs fallback behavior.

Remaining:
- No streaming responses yet.
- Provider failure diagnostics can still be refined beyond the current user-facing error hints.

## 2026-05-11 update: company AI model settings

Implemented:
- Settings > AI now exposes company model choices from the dev-guide document.
- Users only need to choose a model and enter their own AI Key from "My AI Key".
- The AI Key is stored only in local `.noteapp/settings.json`; snapshots expose only `api_key_configured`.
- AI Wiki Ask now prefers local settings provider config before environment variables.
- Provider dispatch supports `openai-completions`, `anthropic-messages`, and `google-generative-ai`.
- Settings > AI can test the configured provider through bridge `/api/ai/provider/health`.
- Ask UI now explains provider fallback, bridge route errors, and no-citation next steps.

Remaining:
- No streaming answer UI yet.
