# v1.0.43 Managed Database And Backup Plan

Date: 2026-05-19

This plan closes the current PROD-02 boundary for the sync backend. The codebase
still uses the SQLite repository profile, but production configuration must keep
the database path explicit and separate from local dev/test state.

## Deployment Profiles

| Profile | Environment | Repository | Purpose |
| --- | --- | --- | --- |
| Development | default or `NOTEAPP_SERVER_ENV=development` | JSON or SQLite | Local runs and focused tests |
| Test/CI | `NOTEAPP_SERVER_ENV=test` or unset | Temporary JSON/SQLite | Unit, smoke, and E2E gates |
| Production | `NOTEAPP_SERVER_ENV=production` | SQLite only | Deployed sync server state |

Production mode rejects `NOTEAPP_SERVER_STORAGE=json`, requires
`NOTEAPP_SERVER_DATA_DIR`, and requires an absolute database path through
`NOTEAPP_SERVER_DATABASE_URL` or `NOTEAPP_SERVER_SQLITE_PATH`.

## Migration Path

1. Stop write traffic or run the import during an approved maintenance window.
2. Back up the current JSON state if migrating from dev/test JSON state.
3. Run:

```powershell
python apps\backend\noteapp-server\scripts\import_json_state_to_sqlite.py `
  --json-state apps\backend\noteapp-server\.data\sync-state.json `
  --sqlite-db C:\noteapp-prod\noteapp-server.sqlite3
```

4. Start the server with:

```powershell
$env:NOTEAPP_SERVER_ENV='production'
$env:NOTEAPP_SERVER_STORAGE='sqlite'
$env:NOTEAPP_SERVER_DATA_DIR='C:\noteapp-prod\data'
$env:NOTEAPP_SERVER_SQLITE_PATH='C:\noteapp-prod\noteapp-server.sqlite3'
```

5. Verify `GET /health/dependencies` reports repository type `sqlite` and the
   expected applied schema version.

## Backup And Restore

Create a consistent backup:

```powershell
python apps\backend\noteapp-server\scripts\backup_sqlite.py `
  --sqlite-db C:\noteapp-prod\noteapp-server.sqlite3 `
  --backup-dir C:\noteapp-backups
```

Restore into a fresh drill database:

```powershell
python apps\backend\noteapp-server\scripts\restore_sqlite.py `
  --backup-path C:\noteapp-backups\noteapp-server-YYYYMMDDTHHMMSSZ.sqlite3 `
  --sqlite-db C:\noteapp-prod-drill\noteapp-server.sqlite3
```

Use `--force` only in a planned drill or recovery window, because it replaces the
destination database.

## Rollback Rule

Application rollbacks may restart an older server build against the same forward
compatible schema, but destructive schema rollback is not supported. Before a
schema-changing deployment, take a backup and verify restore into a fresh
database. If the application deployment fails, roll back the application binary
and keep the migrated database unless a tested restore procedure is explicitly
approved.
