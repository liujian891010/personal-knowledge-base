# v1.0.43 Tombstone GC Worker Plan

Date: 2026-05-19

This plan closes the current PROD-04 boundary for background tombstone garbage
collection.

## Runtime Configuration

| Variable | Purpose |
| --- | --- |
| `NOTEAPP_SERVER_TOMBSTONE_GC_WORKER_ENABLED` | Enables the background worker when set to `true` |
| `NOTEAPP_SERVER_TOMBSTONE_GC_INTERVAL_MS` | Worker cadence |
| `NOTEAPP_SERVER_TOMBSTONE_GC_MIN_RETENTION_MS` | Minimum age before a delete marker can be reclaimed |
| `NOTEAPP_SERVER_TOMBSTONE_GC_INACTIVE_AFTER_MS` | Device inactivity window used by GC eligibility |

When `NOTEAPP_SERVER_ENV=production` and the worker is enabled, all worker
timing values must be explicitly configured. The `.env.example` production
baseline uses seven days for retention and inactive-device windows and one hour
for the worker cadence.

## Safety Boundary

Tombstone GC only removes delete markers from the head manifest after:

1. The configured retention window has passed.
2. Every active joined device has acknowledged at least the delete revision.
3. Revoked devices have been removed from the active blocker set.

GC does not delete encrypted blob bytes or file-version records. That keeps
mistaken delete recovery inside the file-version/recovery package boundary
instead of making GC a destructive object-storage cleanup path.

## Background Worker

The worker runs in the FastAPI process, scans all known vault ids, and calls the
same `run_tombstone_gc` store boundary used by the manual endpoint. It records
the latest run summary in health diagnostics and increments
`tombstone_gc_deleted_total` for reclaimed delete markers.

Manual GC remains available at:

```text
POST /vaults/{vault_id}/tombstones/gc
```

The manual endpoint defaults to the same configured retention and inactive
device windows, while still allowing an authorized operator request body to
override `now_ms`, `min_retention_ms`, or `inactive_after_ms` for drills.

## Audit Records

Each recorded run is appended under the vault `tombstone_gc.runs` log with:

1. Run id and timestamp.
2. Base and new revision.
3. Active device ids.
4. Retention and inactive windows.
5. Reclaimed tombstones.
6. Blocked tombstones and blocker devices.
7. Recovery boundary text.

The log is capped by `MAX_TOMBSTONE_GC_LOGS`.

## Verification

Automated coverage:

1. Production worker mode rejects missing retention/cadence configuration.
2. Worker `run_once` scans known vaults and records diagnostics.
3. Existing store tests verify retention blocking, active device ack blocking,
   revoked-device unblock behavior, audit run logging, and manifest advancement.
4. Metrics expose `tombstone_gc_deleted_total`.
