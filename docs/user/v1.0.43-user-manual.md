# NoteAI V1 User Manual

Version: v1.0.43

## Product Boundary

NoteAI V1 is a local-first knowledge base. Your workspace is a folder on your computer, and normal editing, search, backlinks, graph view, attachments, drafts, trash, and AI writeback previews are driven by local files and the local desktop bridge.

Cloud sync is optional infrastructure for moving encrypted workspace changes between your devices. The sync service is not the primary place where you work.

## Install And Upgrade

1. Install NoteAI from the signed Windows installer.
2. Launch the desktop app and choose or create a workspace folder.
3. If the local bridge fails to start, use the desktop diagnostics export before changing the installation.
4. V1 does not enable automatic updates. To upgrade, download the next signed installer and run it over the existing installation.
5. To roll back, run the previous signed installer. Workspace files are stored outside the install directory, so reinstalling the app must not delete your workspace.

## Workspace Basics

1. A workspace is a user-selected folder that contains notes, attachments, and NoteAI metadata.
2. Markdown notes are editable local files.
3. Attachments are imported into the workspace and referenced from Markdown with relative paths.
4. Moving or renaming a note inside the app keeps its stable file identity, so sync, backlinks, and version history can continue to follow the same file.
5. Removing a workspace from the workspace list only removes the registry entry. It does not delete the folder from disk.

## Editing, Drafts, And Trash

1. Edits are written locally first.
2. Draft/autosave state protects in-progress editing, but autosave drafts are not the same as synced file versions.
3. Deleted workspace items move through the trash flow before permanent removal.
4. Empty trash and permanent purge are destructive actions and require explicit confirmation.

## Sync And E2EE

When encrypted sync is enabled, note and attachment blob contents are encrypted on the client before upload. The sync server and object storage receive ciphertext blobs, not plaintext note content.

Important limits:

1. The server still stores sync metadata needed for coordination, such as manifest state, file identity, content hashes, blob IDs, sizes, modified times, device state, and version metadata.
2. E2EE means the cloud cannot decrypt synced content plaintext. It does not mean the cloud sees no metadata.
3. The vault key is not uploaded or escrowed by the server.
4. Unlocking E2EE happens locally. Locking, exiting, or switching vaults clears the in-memory key.

## Recovery Materials

Recovery requires two separate materials:

1. The recovery package file.
2. The recovery phrase that unlocks that package.

Keep both outside the workspace and do not store them together. A recovery phrase alone is not enough. A recovery package alone is not enough. If you lose all unlocked devices and lose either recovery material, encrypted synced content cannot be recovered by the service.

Use recovery when onboarding a new device or restoring access after local secure storage is unavailable. Import the package and enter the phrase on the new device, then sync can download encrypted blobs and decrypt them locally.

## File Version History

File version history is tracked per stable file identity, not only by path. If you rename or move a note inside the app, its history remains attached to the same file.

Version behavior:

1. Successful sync commits can create version records.
2. Manual checkpoints can add labels, notes, and pin state.
3. Autosave drafts do not create cloud file versions.
4. Pinned versions are retained outside normal cleanup rules.
5. Restoring an old version writes that content back into the current file and creates a new commit. It does not roll back the entire workspace.

Use the version panel on a selected file to preview a version, compare a diff, update its label or note, pin/unpin it, or restore it into the current file.

## AI Features

AI features are user-directed tools on top of local workspace context.

1. Summarizing the current note or selected search results sends the chosen context to the configured AI provider.
2. AI writeback uses preview and confirmation. It must not silently overwrite a user-edited note.
3. Inserting an AI answer into the current note writes to the current editor draft first.
4. Saving an AI answer as a new knowledge page creates a normal workspace page and refreshes the local index.
5. `.ai/wiki/`, `.ai/index.md`, and `.ai/AGENTS.md` participate in normal encrypted sync when they exist.
6. `.ai/raw/` and `.ai/log.md` are local-only by default and are not part of the normal sync set.

AI provider keys are stored locally in `.noteapp/settings.json` and are not written into sync data.

## Diagnostics

The desktop diagnostics export is intended for support and release validation. It includes app/runtime information, bridge health, dependency health, local runtime paths, the tail of `desktop-runtime.log`, and previews of bridge state snapshot files.

Treat diagnostics as sensitive operational data. Review the JSON before sharing it outside the development or support team, because paths, account state, workspace registry state, and error messages can reveal private environment details.

## Safe Operating Checklist

1. Keep a normal external backup of important workspace folders.
2. Export and store recovery materials before relying on encrypted sync.
3. Do not assume the service can reset your E2EE key or recover lost recovery materials.
4. Review AI context before sending it to an external provider.
5. Use signed installers only, and keep the previous installer available until the new release is verified.
