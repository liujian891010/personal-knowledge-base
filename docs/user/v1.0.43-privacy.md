# NoteAI V1 Privacy And AI Boundary

Version: v1.0.43

## Summary

NoteAI V1 is local-first with optional encrypted sync and user-directed AI features. The product boundary is:

1. Local workspace files remain the source of truth.
2. Synced blob contents are encrypted before upload.
3. The sync server still sees operational metadata required to coordinate devices.
4. AI provider calls may send the user-selected note or search context to the configured provider.
5. AI writeback requires preview and user confirmation.

## What Stays Local

The following are local by design:

1. The workspace folder and local file contents before sync.
2. Draft/autosave state.
3. The vault key in local secure storage or in process memory after unlock.
4. AI provider key in `.noteapp/settings.json`.
5. `.ai/raw/` local cache and intermediate artifacts.
6. `.ai/log.md` local audit log.
7. Desktop runtime logs and bridge state snapshots unless the user exports diagnostics.

## What Can Sync

When sync is enabled, these workspace assets can sync through the normal encrypted path:

1. Notes and attachments.
2. Manifest metadata needed to identify files, revisions, sizes, hashes, and blob references.
3. File version metadata.
4. Device heartbeat and acknowledged revision state.
5. `.ai/wiki/`, `.ai/index.md`, and `.ai/AGENTS.md` when those files exist in the workspace.

Synced blob payloads are encrypted client-side. The server stores ciphertext and metadata, not plaintext note bodies.

## E2EE Boundary

E2EE protects synced content plaintext from the sync server and object storage. It does not hide every observable property.

The service can still observe metadata needed for product operation, including:

1. Account and device identifiers.
2. Vault identifiers.
3. Revision numbers.
4. File identifiers and version identifiers.
5. Blob identifiers, content hashes, sizes, and modified times.
6. Tombstone and version retention state.
7. Request timing, status codes, and operational logs.

The service does not receive the vault key and cannot decrypt content blobs without user-held key material.

## Recovery Boundary

The recovery package and recovery phrase are user-held materials. NoteAI does not provide server-side key escrow or password recovery for encrypted content.

Recovery succeeds only when the user has both:

1. A valid recovery package for the vault.
2. The matching recovery phrase.

If every unlocked device is gone and either material is lost, encrypted content is not recoverable by the service.

## AI Boundary

AI features run only when the user invokes them. The app may send selected context to the configured provider for:

1. Current-note summary.
2. Search-result summary.
3. AI document chat.
4. AI writeback preview generation.

The sync E2EE guarantee does not apply to data intentionally sent to an external AI provider. Provider retention, logging, and training behavior depends on the selected provider and account configuration.

AI writeback guardrails:

1. AI output is previewed before it is applied.
2. Current-note insertion writes to the draft/editor flow first.
3. New knowledge page writeback creates a normal workspace page with source context.
4. User-edited or locked AI wiki pages must not be silently overwritten.
5. Background silent rewrites of `.ai/wiki/` are not part of the V1 boundary.

## Diagnostics Boundary

Diagnostics export is manual. The exported JSON can contain:

1. App version and runtime details.
2. Bridge health and dependency health.
3. Local runtime paths.
4. Tail of desktop runtime logs.
5. Bridge state snapshot previews.

Diagnostics should be treated as confidential support data. Users should review exports before sharing them.

## Update Boundary

V1 does not use automatic updates. New versions are installed manually from signed installers. This avoids introducing a silent remote code delivery path before release feed, rollback, and updater validation controls are ready.
