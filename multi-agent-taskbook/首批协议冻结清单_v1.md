# 首批协议冻结清单 v1

## 1. 文档目标

本清单用于明确 V1 在多 Agent 并行开发前，哪些协议、边界和规则必须先冻结。

冻结的意思是：

1. 有唯一 owner
2. 有明确字段语义
3. 有固定序列化和兼容规则
4. 未经总控评审不得随意变更

---

## 2. 必须冻结的 6 类内容

### 2.1 Vault 目录结构

必须冻结：

1. `VaultRoot/.vaultinfo`
2. `VaultRoot/.noteapp/`
3. `VaultRoot/.ai/`
4. `VaultRoot/Notes/`
5. `VaultRoot/Attachments/`

关键边界：

1. 文件系统是主存储
2. `Notes/` 和 `Attachments/` 保存主内容
3. `.noteapp/` 保存本地元数据和同步运行态
4. `.ai/wiki/` 是可同步 AI 产物
5. `.ai/raw/` 是本地中间产物，不进入常规跨端同步

owner：

1. AG01 定义
2. AG02 实现

### 2.2 `filemap.json` 语义

必须冻结：

1. `file_id`
2. `path`
3. `type`
4. `status`
5. `active | deleted | conflict_copy`

关键规则：

1. `filemap.json` 是文件身份唯一真相
2. UI 不允许直接写 `filemap.json`
3. 只能由核心层串行写入
4. 只能原子替换，不允许半写入

owner：

1. AG01 定义 schema
2. AG02 实现

### 2.3 `manifest / tombstone` canonical 规则

必须冻结：

1. `manifest` 的字段集合
2. `files[]`
3. `tombstones[]`
4. `revision`
5. 摘要计算方式
6. canonical 序列化规则

关键规则：

1. 不允许不同实现使用不同序列化顺序
2. 不允许客户端和服务端各自发明 hash 语义
3. 必须有 golden fixtures

owner：

1. AG01

### 2.4 `vault_state` 字段定义

必须冻结：

1. `last_applied_revision`
2. `remote_head_revision`
3. `acked_revision`
4. `pending_ack_to_server`
5. `commit_in_progress`
6. `last_manifest_summary`
7. `local_delete_sequence`

关键规则：

1. 所有字段必须明确“谁写、何时写、恢复时如何处理”
2. 不允许前后端各自理解不同

owner：

1. AG01 定义
2. AG03、AG05 实现

### 2.5 同步 API 契约

必须冻结：

1. 设备注册/移除接口
2. head 查询接口
3. commit 接口
4. ack 接口
5. blob `upload-init`
6. blob `download-init`

关键规则：

1. 服务端只做同步中继和授权，不是主真相
2. commit 必须有 CAS 语义
3. 设备移除后，旧下载授权必须可撤销

owner：

1. AG01 定义 DTO / OpenAPI
2. AG04 实现

### 2.6 AI 产物边界

必须冻结：

1. `.ai/wiki/` 参与常规跨端同步
2. `.ai/index.md` 参与同步
3. `.ai/AGENTS.md` 参与同步
4. `.ai/log.md` 不参与常规同步
5. `.ai/raw/` 不参与常规同步

关键规则：

1. 问答优先基于 `.ai/wiki/`
2. `.ai/raw/` 是缓存和中间产物
3. V1 不允许把 `.ai/raw/` 纳入 manifest 或常规 sync set

owner：

1. AG01 定义
2. AG06 实现

---

## 3. 首批必须产出的冻结物

在 `packages/protocol/` 中至少产出：

1. `schemas/manifest.schema.json`
2. `schemas/filemap.schema.json`
3. `schemas/tombstone.schema.json`
4. `schemas/vault-state.schema.json`
5. `schemas/wiki-page.schema.json`
6. `fixtures/manifest/`
7. `fixtures/filemap/`
8. `fixtures/vault-state/`
9. `openapi/sync-api.yaml` 或等价文件

---

## 4. 首批必须形成的书面说明

在 `docs/contracts/` 中至少形成：

1. `manifest.md`
2. `filemap.md`
3. `sync-api.md`
4. `ai-boundary.md`

每份文档至少回答：

1. 数据结构是什么
2. 谁负责写入
3. 谁负责读取
4. 崩溃恢复如何处理
5. 哪些字段禁止随意扩展

---

## 5. 哪些内容现在不能冻结过细

以下内容现在只冻结边界，不冻结实现细节：

1. 具体前端 UI 样式
2. 具体编辑器选型
3. AI 模型供应商
4. 向量引擎或全文检索的最终实现细节
5. 桌面端和移动端框架选型

原因：

1. 这些内容不应阻塞协议层
2. 这些内容后续允许在不破坏协议的前提下替换

---

## 6. 冻结验收标准

协议冻结完成时，至少满足：

1. 有 schema
2. 有文档
3. 有 fixtures
4. 有 owner
5. 有版本说明
6. 有兼容性约束

如果缺少其中任一项，则不能视为“已冻结”。

---

## 7. 变更控制规则

冻结后，任何协议变更都必须回答：

1. 为什么要改
2. 是否破坏已有 fixtures
3. 是否影响 `filemap.json` / `manifest` / `vault_state`
4. 是否影响服务端 API
5. 是否需要 migration 或兼容路径

---

## 8. 一句话执行建议

先把共享协议冻硬，再放开并行开发；不要让多个 Agent 在实现阶段反向定义协议。
