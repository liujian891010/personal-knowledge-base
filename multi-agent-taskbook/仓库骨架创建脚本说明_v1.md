# 仓库骨架创建脚本说明 v1

## 1. 文档目标

本文件用于指导首批仓库骨架初始化，重点解决三件事：

1. 目录先怎么建
2. 占位文件先怎么放
3. 哪些文件内容必须一开始就满足现有 MonoRepo 规范

本文件是“初始化说明”，不是最终技术实现文档。

## 4. 关键占位文件模板

### 4.1 前端 `.cicd.env`

文件路径：

`apps/frontend/noteapp-web/.cicd.env`

建议内容：

```bash
cicd_monorepo_type='static'
cicd_monorepo_name='noteapp-web'
# 如果不希望服务器构建静态资源，则打开下面这一行
# cicd_build_static='false'
```

说明：

1. 如果前端打包依赖高版本 Node，则应尽早决定是否走预构建产物
2. 如果走预构建产物，要让 `AG07` 在任务中明确提交 `dist/` 或对应产物目录

### 4.2 后端 `.cicd.env`

文件路径：

`apps/backend/noteapp-server/.cicd.env`

建议内容：

```bash
cicd_monorepo_type='python'
cicd_monorepo_name='noteapp-server'
```

### 4.3 后端 `requirements.txt`

文件路径：

`apps/backend/noteapp-server/requirements.txt`

建议首批内容：

```txt
fastapi
uvicorn
pydantic
```

说明：

1. 这里只是骨架期最小依赖
2. SQLite、AI、对象存储等依赖由后续专项 Agent 按实际实现补齐

### 4.4 后端 `main.py`

文件路径：

`apps/backend/noteapp-server/main.py`

建议首批内容：

```python
from fastapi import FastAPI

app = FastAPI(title="noteapp-server")


@app.get("/health")
def health():
    return {"ok": True}
```

说明：

1. 只作为部署骨架和健康检查占位
2. 不代表最终模块结构

### 4.5 `config/nacosConfig.py`

文件路径：

`apps/backend/noteapp-server/config/nacosConfig.py`

建议保留构建脚本可替换字段：

```python
HOST = ""
PORT = ""

NACOS_NAMESPACE = ""
NACOS_SERVER_ADDR = ""
NACOS_USERNAME = ""
NACOS_PASSWORD = ""
NACOS_SERV_NAME = ""
NACOS_SERVICE_IP = ""
NACOS_SERVICE_PORT = ""
NACOS_DATA_ID = ""
```

说明：

1. 字段名不要改
2. 值可以先留空

## 5. 首批 README 应该写什么

### `README.md`

根目录 README 首批至少写明：

1. 这是一个 Monorepo
2. 当前包含哪些子项目
3. 哪些目录是 deployable project
4. 哪些目录是 shared packages

### `apps/frontend/noteapp-web/README.md`

至少写明：

1. 这是 Web 前端项目
2. 部署类型是 `static`
3. 构建方式是否依赖服务器构建

### `apps/backend/noteapp-server/README.md`

至少写明：

1. 这是 Python 后端服务
2. 启动方式基于 `uvicorn`
3. 会接入同步 API 和 AI 能力

### `packages/protocol/README.md`

至少写明：

1. 本目录是全仓库共享契约唯一来源
2. 不允许其他模块维护第二份 schema/DTO 真相

## 7. 初始化阶段建议用的命名

### 项目名

1. 前端项目名：`noteapp-web`
2. 后端项目名：`noteapp-server`

### 包名

1. 协议：`protocol`
2. 本地存储与同步核心：`vault-core`
3. AI 核心：`ai-core`
4. 测试夹具：`test-fixtures`

### 文档名

建议统一使用：

1. `README.md`
2. `*-plan.md`
3. `*-schema.json`
4. `*-overview.md`

---

## 8. 初始化阶段不要做的事

1. 不要在骨架阶段就创建多个后端服务
2. 不要一开始就把桌面端和移动端并入 `apps/`
3. 不要先写大量业务代码再回头补 `.cicd.env`
4. 不要在 `apps/backend/` 和 `packages/protocol/` 各写一套 API 类型
5. 不要在前端项目里先绑定高版本 Node 特性，再考虑部署约束

---

## 9. 推荐初始化执行顺序

### 第一步：搭 deployable project

1. 建 `apps/frontend/noteapp-web/`
2. 建 `apps/backend/noteapp-server/`
3. 放好两个 `.cicd.env`

### 第二步：搭 shared packages

1. 建 `packages/protocol/`
2. 建 `packages/vault-core/`
3. 建 `packages/ai-core/`
4. 建 `packages/test-fixtures/`

### 第三步：搭客户端目录

1. 建 `clients/desktop/`
2. 建 `clients/mobile/`

### 第四步：搭文档与测试目录

1. 建 `docs/`
2. 建 `tests/e2e/`

### 第五步：补最小运行骨架

1. 后端补 `main.py`
2. 后端补 `requirements.txt`
3. 后端补 `config/nacosConfig.py`
4. 前后端补各自 README

---

## 10. 初始化完成后的最小检查

初始化完成后至少确认：

1. `apps/frontend/noteapp-web/.cicd.env` 存在
2. `apps/backend/noteapp-server/.cicd.env` 存在
3. `apps/backend/noteapp-server/requirements.txt` 存在
4. `apps/backend/noteapp-server/config/nacosConfig.py` 存在
5. `packages/protocol/` 已建立
6. `docs/` 已建立

---

## 11. 一句话执行建议

骨架阶段只解决“目录、约束、占位和部署识别”，不要提前把复杂实现揉进去；骨架越稳，后续多 Agent 并行成本越低。
